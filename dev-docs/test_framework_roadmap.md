# StreamDeck — Test Framework Roadmap

**Status:** Authoritative spec for building the automated test framework.
**Audience:** the `test-engineer` agent (`.claude/agents/test-engineer.md`) and humans.
**Companion docs:** `dev-docs/test_plan.md` (what to test and why),
`.claude/skills/test-authoring/SKILL.md` (how to write tests here),
`dev-docs/streamdeck_product_roadmap_2026.md` (product scope), `CLAUDE.md` (conventions).

Each item below is **one agent session's worth of work**. Implement exactly one item at a
time, in order, unless the dependency column says otherwise. An item is done only when its
**Acceptance** passes via `bash scripts/verify.sh <gate>`.

---

## Why this exists

The 2026-10 dependency uplift (Vite 8, React 19, TypeScript 7, Vitest 5, quick-xml 0.42,
sysinfo/ts-rs/thiserror majors) exposed the limits of the current gate:

- `verify.sh` is green but cannot prove the app *works*: it never launches the app, never
  exercises real IPC, and never checks what reaches the presentation window.
- React 19 / Vite 8 were validated by hand in a browser; the app itself by a manual launch.
- A parser upgrade (quick-xml 0.42) may silently change text handling (e.g. `&amp;`) with no
  fixture to notice.
- Five earlier multi-window/IPC bugs were found only by manual launch (see `CLAUDE.md`).

**Goal:** make "did the upgrade / change break the product?" answerable by a local command
in minutes, with layered tests that localise failures, while spending **zero extra CI
minutes by default**.

## Principles (apply to every item)

1. **Test the product, not the mock.** Prefer real Rust + real event bus; mock only the OS
   boundary (native dialog, displays) and the webview-less layers.
2. **Layered, cheapest-first.** A bug should be caught at the lowest layer that can see it;
   the E2E layer is for wiring and journeys, not logic.
3. **A test must be able to fail.** Every new test is proven by a deliberate fault (see skill
   "Prove it can fail"). Green-by-construction tests are worse than none.
4. **Local-first, CI-light.** Metered CI (macOS 10x, Windows 2x): only layers L0–L3 run in
   CI; L4/L5 run locally via `verify.sh e2e` or manual `workflow_dispatch`.
5. **No weakening of the product to enable tests.** Respect `CLAUDE.md` invariants: the
   presentation window stays listen-only; no test control server or `withGlobalTauri` in
   release builds; test seams are compiled out of release (`cfg(debug_assertions)` or a
   Cargo feature `e2e`).
6. **Deterministic data.** Fixtures live in `src-tauri/tests/fixtures/` (regenerated by
   `node dev-docs/test-assets/make_test_assets.cjs`). No test depends on the user's real
   app-data directory.

## Layer model

| Layer | Name | Tooling | Runs in | Catches |
|---|---|---|---|---|
| L0 | Static | `cargo clippy -D warnings`, `cargo fmt --check`, `tsc`, Biome, `cargo deny`, invariant greps | `verify.sh core`, CI | type/lint/license/advisory/architecture drift |
| L1 | Unit | `#[test]`, Vitest | `verify.sh core`, CI | pure logic (state machine, stores, parsers) |
| L2 | Integration (no webview) | Rust: `tauri::test` mock runtime + real `EventBus`; JS: Vitest + Testing Library + `mockIPC` | `verify.sh core`, CI | command→bus→payload wiring, component rendering, event→store→UI |
| L3 | Contract/golden | fixture decks + snapshots, ts-rs/event-union drift, capability-file assertions | `verify.sh core`, CI | silent parser/serialization/permission changes |
| L4 | Real-app E2E | Playwright over WebView2 CDP (primary), WebdriverIO embedded (fallback) | `verify.sh e2e`, local / manual dispatch | multi-window wiring, real IPC, what the presentation shows |
| L5 | Manual | checklist in `test_plan.md` §9 | before release / after Tauri-level bumps | hardware: multi-display, projector, global keys, native dialog |

## Phase T0 — Foundations & hygiene

**Goal:** a trustworthy base before adding layers. **Gate:** `bash scripts/verify.sh t0`

### T0.1 — Fix the `verify.sh` hook trigger
**Problem:** `.claude/settings.json` hook `if: Bash(git push*)` is not honoured for compound
commands (e.g. `eval "$(fnm env …)"`), so `pre-push-verify.sh` runs `verify.sh core` on
*every* Bash call and blocks all shell use while the tree is mid-edit.
**Work:** at the top of `.claude/hooks/pre-push-verify.sh`, read the tool-call JSON from
stdin and `exit 0` unless it contains `git push`.
**Acceptance:** with a deliberately failing tree, an unrelated Bash command runs; a
`git push` is still blocked. (Hooks are guardrails — a human must approve this edit.)
**Deps:** none.

### T0.2 — Add `cargo fmt --check` to the gate
`main` currently fails `cargo fmt --check` (e.g. `app.rs` import order). Run `cargo fmt`
once in its own commit, then add the check to `verify.sh core`.
**Acceptance:** `verify.sh core` includes and passes a fmt check; CI runs it too.

### T0.3 — Test conventions & layout
Create the directory contract (document it in the skill, create empty dirs with READMEs only
where needed): 
```
src-tauri/tests/            Rust integration tests (one file per area) + fixtures/
controller/src/**/*.test.ts(x)    co-located unit/component tests
controller/src/test/        shared setup, mockIPC helpers, render helpers
presentation/src/test/      same
e2e/                        L4 harness (own package.json), specs/, pages/, fixtures/
```
**Acceptance:** documented in the skill; `verify.sh` structural check asserts the dirs exist.

### T0.4 — Coverage visibility (no thresholds yet)
Vitest `--coverage` (v8) in both frontends; `cargo llvm-cov` optional. Report only; record
baseline in `test_plan.md` §12.
**Acceptance:** `npm run test:coverage` works in both; baseline numbers recorded.

## Phase T1 — Rust integration tests (L2, no webview)

**Goal:** assert the real command→bus→payload behaviour. **Gate:** `bash scripts/verify.sh t1`

### T1.1 — Mock-runtime harness
Add a test helper that builds a `tauri::test::mock_builder()` app with the same `.manage()`
state as `app.rs` (bus, state machine, scene, config) and a temp app-data dir, and a
`collect_events(bus)` utility that subscribes before acting and returns the `AppEvent`s
seen. **Do not duplicate `app.rs` wiring by hand if it can be extracted** — prefer extracting
a `build_state()` function that both `app.rs` and tests call (keeps `app.rs` gated per
invariant 7).
**Acceptance:** one test boots the mock app and round-trips `get_build_info` via the IPC
test helper.

### T1.2 — Deck & slide command journeys
Tests for: `deck_import` (fixture .pptx) → `DeckImportProgress`* then `SlideUpdate` with
`index 0`, correct `total`/`title`/`body`; `slide_advance` / `slide_rewind` / `slide_jump_to` incl. `DeckEnd`/`DeckStart`
emitted *instead of* `SlideUpdate`; `deck_clear` → `SlideUpdate{total:0}` +
`SceneSourceChanged{SlideDeck}` + `active_deck_id.txt` removed; `deck_restore`.
**Acceptance:** each command has ≥1 happy and ≥1 error/boundary test asserting exact
payloads; all pass under `cargo test`.

### T1.3 — Scene, timer, display, config commands
Same treatment for `scene_push_image/video` (size-limit rejection happens in Rust, before
copy), `scene_set_source`, timer start/elapsed, display assignment fallback on
`DisplayLost`, and TOML hot-reload (write file → `ConfigReloaded`).
**Acceptance:** limits and fallbacks asserted, not just happy paths.

### T1.4 — Architecture invariants as tests
Turn `CLAUDE.md` invariants into executable tests so `verify.sh` greps are backed by logic:
- parse `src-tauri/capabilities/presentation.json` → permissions ⊆ `{core:event:default}`
  (no invoke permission) and `windows` contains `presentation`;
- every `AppEvent` variant serialises to `{type, payload}` (discriminated union);
- no `.unwrap()` in `commands/` (already grep-gated — keep).
**Acceptance:** a regression (adding `core:default` to presentation) fails a test.

## Phase T2 — Frontend render & wiring tests (L2, JS)

**Goal:** cover what users see without launching the app. **Gate:** `bash scripts/verify.sh t2`

### T2.1 — Shared test utilities (both frontends)
`src/test/mockTauri.ts`: `installMockIPC(handlers)` wrapping `@tauri-apps/api/mocks`
`mockIPC({ shouldMockEvents: true })`, `emitAppEvent(event)`, `renderApp()` with providers,
`afterEach(clearMocks)`. Remember jsdom lacks WebCrypto — polyfill in setup (see Tauri docs).
**Acceptance:** helper has its own test proving `invoke` is intercepted and events delivered.

### T2.2 — Controller component tests
`App` + `SlideDeckPanel` + `PresentButton` + `SceneMediaPanel` + `DisplayPanel` with
`mockIPC`: empty state ("No slides yet", Import CTA, Present disabled), loaded state
(thumbnail strip, counts, `layout_unsupported` badge), Prev/Next/Jump invoke the right
commands with the right args, Clear Deck calls `deck_clear`, import error/progress display.
Query by role/label/text — never by CSS class.
**Acceptance:** each component has tests for each visible state; user-event, not
`fireEvent`.

### T2.3 — Presentation app tests
Emit `SlideUpdate`, `DeckEnd`, `SceneSourceChanged`, media events → assert rendered DOM
(title/body/background/media element, empty state). Presentation must never call `invoke`
(assert `mockIPC` handler is never hit).
**Acceptance:** "listen-only" is enforced by test; all event variants rendered or
intentionally ignored (explicit test).

### T2.4 — Event-union exhaustiveness
A type-level + runtime test that the TS `AppEvent` union covers every Rust variant name
(read variants from `src-tauri/src/events.rs` or ts-rs output) in both frontends.
**Acceptance:** adding a Rust variant without a TS variant fails the suite.

## Phase T3 — Golden & contract tests (L3)

**Goal:** make silent upgrades loud. **Gate:** `bash scripts/verify.sh t3`

### T3.1 — Importer fixture matrix
Extend `make_test_assets.cjs` + `src-tauri/tests/deck_import_fixtures.rs` with fixtures for:
`&amp; &lt; &quot;` in titles/body, unicode/emoji/RTL, empty slide, title-only, multi-paragraph
body with bold/italic/size/colour/alignment, nested lists (`lvl`), self-closing vs
start/end `<p:ph>`, unknown placeholder (`layout_unsupported`), 50+ slides (progress events),
corrupt zip, wrong extension. **First task: decide and assert the intended `&amp;` behaviour**
(quick-xml 0.42 emits entity references as separate events; the importer currently ignores
them — confirm whether text is truncated and fix if so).
**Acceptance:** golden JSON snapshots (insta or hand-rolled) of the parsed `SlideDeck`; a
quick-xml bump that changes output fails with a readable diff.

### T3.2 — Serialization/binding drift
ts-rs is currently used only for `commands/system.rs` (`#[ts(export)]`); `AppEvent` and
`SlidePayload` have hand-written TS. Decide whether to extend ts-rs to them; either way,
snapshot the serde JSON of every `AppEvent` and `SlidePayload` variant and compare against
committed JSON that the TS tests (T2.4) also load.
**Acceptance:** changing a payload field breaks both Rust and TS suites until both updated.

### T3.3 — PDF path guard
The pdfium decision is open (see `CLAUDE.md`). Keep the `#[ignore]`d test, add a test that
asserts the *absence* of the library produces a typed `AppError` (not a panic) once binding
is switched to `bind_to_library`. **Blocked on the pdfium decision — do not start without it.**

## Phase T4 — Real-app E2E (L4)

**Goal:** launch the real app, click, and verify what reaches the presentation screen.
**Gate:** `bash scripts/verify.sh e2e` (local only; not in `core`).

### T4.0 — Spike: prove the harness (decision gate)
Time-box ~2h. Build the app, launch with
`WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=<port>` and a per-run
`WEBVIEW2_USER_DATA_FOLDER`, attach with Playwright `chromium.connectOverCDP`.
Answer, in `dev-docs/e2e-spike-findings.md`:
1. Do **both** windows (controller + hidden presentation) appear in `context.pages()`?
2. Can the test click controller buttons and read the presentation DOM?
3. Does `window.__TAURI_INTERNALS__.invoke` work from `page.evaluate` in the controller (so
   tests can call `deck_import` with a fixture path and avoid the native dialog)?
4. Does the hidden presentation window render/update while `visible(false)`?
5. Dev-server build vs production-like build (`cargo tauri build --no-bundle`): which is
   usable, and which should be the default?
**Decision:** if 1–3 hold → proceed with Playwright/CDP. If not → switch the harness to
WebdriverIO `@wdio/tauri-service` (embedded provider, feature-gated plugin) and amend this
roadmap before T4.1.

### T4.1 — App-data isolation seam
Tests must not touch the real `%APPDATA%` deck state. Not implemented yet: add a debug/`e2e`-only override
(proposed env name `STREAMDECK_DATA_DIR`, does not exist in the code) read where `app_data_dir()` is resolved
(`app.rs`, `commands/deck.rs`). Compiled out of release.
**Acceptance:** with the env var set, no files are written to the real app-data dir; a unit
test covers the resolution function; release build ignores the variable.

### T4.2 — Harness package
`e2e/` with its own `package.json` (Playwright), `playwright.config.ts` (workers: 1 — one
app instance owns the screen; fixtures own port + user-data folder + data dir + process
lifecycle with `taskkill /T /F` teardown), `pages/ControllerPage.ts`,
`pages/PresentationPage.ts` (all locators live here), `fixtures/app.ts` (`app`,
`controller`, `presentation`), and `waitForAppReady` keyed on a real signal (not sleep).
`scripts/verify.sh e2e` builds (hash-cached) then runs it.
**Acceptance:** `verify.sh e2e` runs a smoke test that launches, asserts both windows exist,
and tears down with no leaked processes.

### T4.3 — Core journeys
Implement J1–J8 from `test_plan.md` §6 — each asserts **controller state and presentation
DOM** after every action, plus window state via backend where relevant. One spec file per
journey; independent; each creates its own data dir.
**Acceptance:** all journeys green 5× consecutively (`--repeat-each=5`) with no retries.

### T4.4 — Failure artifacts & diagnosis
On failure: trace, screenshots of *both* windows, app stdout/stderr log, event log.
`e2e/README.md` documents "how to read a failure".
**Acceptance:** a deliberately broken build produces a report that localises the failing
layer within one read.

## Phase T5 — Visual regression & upgrade protocol

**Gate:** `bash scripts/verify.sh t5`

### T5.1 — Visual baselines (local)
`toHaveScreenshot` for: controller empty / loaded / presenting; presentation with title-only,
body-heavy, `layout_unsupported`, media, empty. Fixed viewport, animations disabled,
fonts bundled/pinned. Baselines are machine-local (gitignored) unless fonts are pinned.
**Acceptance:** an intentional CSS change fails with a visible diff; `--update-snapshots`
documented.

### T5.2 — `scripts/update-deps.sh`
Codifies the manual uplift: isolated worktree per package set → apply → `verify.sh core` →
`verify.sh e2e` → classify PASS / NEEDS-ATTENTION / BAD-PR → report; restores `main` state
always (lesson: failed `npm ci` left stale `node_modules`). Coupled sets are one unit:
`{vite, @vitejs/plugin-react, vitest}`, `{react, react-dom, @types/*}`, `{@tauri-apps/*,
tauri*}`.
**Acceptance:** runs against a seeded old lockfile and produces a correct report.

### T5.3 — Optional CI lane
`workflow_dispatch`-only Windows job running `verify.sh e2e` and uploading the Playwright
report. Never on `pull_request`.
**Acceptance:** manual dispatch passes; documented cost note (Windows = 2x minutes).

## Phase T6 — Test quality guards

**Gate:** `bash scripts/verify.sh t6`

### T6.1 — False-green scanner
`scripts/scan-tests.sh` (deterministic grep/ast rules, exits non-zero on hit): `.only`,
`.skip` without issue link, `waitForTimeout`/`sleep` in e2e, empty `catch`, `expect(...)`
without matcher, missing `await` on Playwright `expect`, `force: true` without comment, tests
with no assertion, CSS-class selectors in e2e, `unwrap()` in test helpers that hide errors.
Wired into `verify.sh core` for changed test files.
**Acceptance:** a seeded-bad fixture file trips every rule.

### T6.2 — Mutation spot-checks
`cargo mutants` on `slide_state_machine.rs` and `deck_importer.rs` (local, on demand);
Stryker optional for stores. Surviving mutants become new tests.
**Acceptance:** documented procedure; initial survivors triaged.

### T6.3 — Flake policy & coverage thresholds
Quarantine tag + owner + expiry; E2E rerun policy (no retries in gate; one diagnostic
rerun allowed manually). Introduce coverage floors from the T0.4 baseline.
**Acceptance:** thresholds enforced in `verify.sh core`; quarantine list is empty or dated.

### T6.4 — Post-edit lint hook (needs human approval)
Hook that runs `scan-tests.sh` on edited files under test dirs and feeds violations back.
**Acceptance:** editing a test to add `.only` surfaces the violation immediately.

## Phase T7 — Extension points for live production (branch `feature/live-production`)

No work on `main`; design hooks so camera/NDI/streaming features (developed on `feature/live-production`) are testable without hardware:
GStreamer `videotestsrc`/`audiotestsrc` fakes behind a trait; NDI/WHIP sources faked at the
pipeline boundary; stream-health events asserted on the bus (L2) before any real-device E2E.
Each new product feature's `run_fX_Y()` gate must declare which layers it adds tests to.

## Working agreement for the agent

- One roadmap item per session. Read this file's item, `test_plan.md` for the target
  behaviour, and the `test-authoring` skill before writing any test.
- Each item: write tests → run → **prove they can fail** → add/extend the `verify.sh` gate →
  update `test_plan.md` traceability + `CLAUDE.md` status → report.
- Never run git write commands. Never edit hooks, `settings.json`, or CI workflows without
  explicit approval (guardrails).
- Record every new lesson in the skill's `references/lessons.md`, not in handoff docs.
- If the code contradicts the plan (e.g. a command was renamed), trust the code, fix the
  plan, and say so in the report.
